If something is wrong, start here

Nine times out of ten it is one of these three.

“Nothing is being blocked”

Your devices are still using the old DNS. Check, in this order:

  • Does the dashboard show look-ups from devices other than the Pi itself? If not, the router change hasn't taken.
  • Did you leave a second DNS server in the router (like 8.8.8.8)? Remove it — devices will prefer it half the time.
  • Did you reboot the device you are testing with? It keeps its old settings until its lease renews.
  • Is the DNS setting under DHCP/LAN rather than Internet/WAN? The WAN one only changes what the router itself uses.

“A website or app stopped working”

  • Press Pause 5 min in the dashboard and try again. If it still fails, it was never us.
  • If it works while paused: open Query log, filter by that device, find the red blocked line that mentions the service, press allow.
  • Still awkward? Drop the protection level a notch in Settings → Blocklists, or switch off whichever list caused it.

“The whole internet died”

If the Pi is unplugged, off, or its address changed, devices pointed at it have no phone book at all.

  • Short term: set your router's DNS back to automatic. Everything works again instantly.
  • Then: reserve the Pi's address in your router (step 6 of the guide) so it can never move.
  • Check the Pi is alive: ping adblockerpro.local.

Questions people actually ask

Will this block YouTube ads?

No, and nothing that works this way can. YouTube serves its ads from the same addresses as the videos, so blocking the address blocks YouTube. For YouTube specifically you still want a browser extension or a premium subscription.

Will it slow down my internet?

The opposite, slightly. Look-ups are answered from the Pi's memory in under a millisecond, popular addresses are refreshed before they expire, and the ads that never download are bandwidth you keep.

What happens if the Pi dies or I unplug it?

Devices pointed at it lose DNS, which looks like “no internet”. Set the router's DNS back to automatic and everything returns immediately. If you want belt-and-braces, run the Pi's own DHCP server — then there is one place to change, not many.

Is my browsing history being sent anywhere?

No. There is no account, no cloud and no telemetry. Look-ups are stored on the Pi's own card (30 days by default) purely so you can look at the graphs. Turn the history off in Settings and nothing is written at all. You can also store client addresses hashed.

Does it work on Wi-Fi, or does it need a cable?

Both work. A cable is more reliable, and “the thing the whole house depends on for DNS” is exactly the device you want wired.

What about phones on mobile data?

Off your Wi-Fi they are not filtered. You can enable DNS-over-HTTPS in Settings and point a phone at the Pi from anywhere, but that means exposing it to the internet — only do that if you understand the trade-off.

Can I block specific sites, like social media at homework time?

Yes — Rules for permanent blocks, Schedules for time windows, and both can target a group of devices so the adults are unaffected.

How is this different from Pi-hole?

Same idea, different implementation. This one is a single Go program with no dependencies, which makes it small and simple to install, and it adds a few things Pi-hole doesn't do natively: encrypted upstream look-ups, scheduled rules, a cache that survives a reboot. Pi-hole is older and more battle-tested, and does its own DNSSEC validation. Both are free; neither will mind if you try the other.

Can I run it on something other than a Pi?

Yes. Any Debian or Ubuntu machine, including an old laptop or a mini PC, and the installer handles 64-bit PCs as well as every Pi.

How do I undo the whole thing?

Set your router's DNS back to automatic, then on the Pi:

sudo systemctl disable --now adblockerpro

That's it. Nothing else on your network was modified.

How do I update it?

Re-run the installer; it replaces the binary and restarts the service, keeping your settings:

curl -fsSL https://raw.githubusercontent.com/ahardkore/adblockerpro/main/deploy/install.sh | sudo bash
I forgot the dashboard password.

On the Pi: sudo adblockerpro -set-password, then press Enter on an empty line to remove it entirely.

Useful commands, if you like that sort of thing

abpctl status            # overview: queries, block rate, upstream health
abpctl tail -f           # live query log in the terminal
abpctl device 192.168.1.21   # what has that TV been asking for?
abpctl pause 15m         # stop filtering for a bit
abpctl check ads.example.com # would this be blocked, and why?

systemctl status adblockerpro    # is the service healthy?
journalctl -u adblockerpro -f    # live logs

Still stuck? Open an issue on GitHub with the output of abpctl status and we'll take a look.
